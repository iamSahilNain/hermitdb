# bench/results — output format

Everything in this directory except this file and `.gitkeep` is generated by
`../run_bench.sh` and gitignored: numbers only enter the repo by being pasted
into the README table, and only from a full run on stated hardware
(honesty rule, SPEC §7).

## Layout per run

```
raw_<UTC-stamp>/                    one directory per invocation
  <config>_P<pipeline>.csv          redis-benchmark --csv output
  <config>_P<pipeline>.err          redis-benchmark stderr
  server_<config>.log               the benched server's own stdout/stderr
  skipped.txt                       configs that refused to start (one per line)
  fsync_micro.txt                   the fsync microbenchmark result
table_<UTC-stamp>.md                the emitted markdown summary
```

`<config>` names: `hermit_t{1,2,4,8}_nofsync`, `hermit_t1_wal_{always,everysec,no}`,
`redis_baseline`. A config that cannot run yet (e.g. `--threads>1` before CP5,
`--wal` before CP4) is SKIPPED and recorded — skipping is loud, never silent.

## Raw CSV schema (from `redis-benchmark --csv`)

```
"test","rps","avg_latency_ms","min_latency_ms","p50_latency_ms","p95_latency_ms","p99_latency_ms","max_latency_ms"
"SET","181818.19","0.152","0.024","0.135","0.279","0.367","0.599"
```

One row per op (SET/GET/INCR). The emitted table keeps `rps`, `p50`, `p99`.

## Emitted table schema

```
| config | op | ops/sec | p50 ms | p99 ms |
```

followed by the skipped-config list and the fsync line:

```
fsync cost on this disk: <N> us per fsync (200 samples, 64B appends)
```

## Caveats for real runs

- **Run on Linux metal (or a VM with a real disk) for publishable numbers.**
  Inside Docker Desktop on macOS, disk I/O crosses virtiofs — the fsync
  microbench measured ~394 µs there, which says more about the virtualization
  layer than any SSD. The fsync row is the money row; don't publish it from a
  Mac-hosted container.
- Default `N_REQUESTS=1000000` per SPEC §7; override (e.g. `N_REQUESTS=20000`)
  only for smoke-testing the harness itself.
- Record hardware (CPU, disk, kernel) alongside any table pasted into the
  README.
